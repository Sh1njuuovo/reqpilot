- 运行深度：`local-full-run`（真实 LLM 全链路跑通）

## 推荐版本（Agent 平台 / LLM 应用侧重）

1. 独立设计并实现 LLM 驱动的需求工程 Agent ReqPilot，用 LangGraph 编排"需求解析 → 领域知识检索 → 产品/前端/后端/测试四角色并行审查 → 去重与严重度收敛 → 结构化 PRD → 单文件交互原型 → 任务拆分"全链路。
2. 在固定管线之外实现沙箱内的目标循环：模型自主选择工具（ls/read/write/edit/grep/find/只读 bash）推进目标，上下文按 token 预算压缩，长期结论落盘；目标完成不采信模型声明，由程序侧校验工作区文件后才判定完成，步数预算用尽即失败。
3. 为工具执行设计安全边界：单目录路径约束让越界访问直接报错，bash 只允许只读白名单且不经 shell 执行，禁用 `find -exec` 与 `sort -o` 这类能把只读命令变成写操作的参数。
4. 以 Pydantic/JSON Schema 约束 LLM 输出，实现一次 schema 修复 + 指数退避重试 + typed error 追踪，失败时明确标记 run 为 failed、不产出伪结果；面向模型过度标注设计跨角色去重 + 每角色按严重度保留 Top-5 的收敛护栏。
5. 构建 12 条人工评审视角样例评测集（DeepSeek 实测成功率 12/12、问题召回 93.8%、单条平均 14.1s），并实现提示词变体自动对比选优；125 个测试、93% 行覆盖率、GitHub Actions CI 全绿，并提供 FastAPI 服务与 MCP stdio server。

## 版本二（后端工程侧重）

1. 独立实现 ReqPilot 需求工程 Agent：LangGraph 状态机 + 四角色并行审查 + 可插拔 RAG + 结构化 PRD/原型/任务生成，LLM 为唯一执行引擎。
2. 实现沙箱内 Agent 循环：工作区路径约束、只读命令白名单、不经 shell 的命令执行、步数预算、程序侧目标校验、上下文压缩与长期记忆落盘。
3. 设计 LLM 可靠性管线：Pydantic 结构化输出 + 一次修复 + 3 次退避重试 + typed error trace；问题去重与每角色 Top-5 收敛，输出可人工审阅。
4. 提供 FastAPI 服务、CLI 六命令、MCP stdio server，统一 AgentRun 追踪与指纹，支持人工确认中断。
5. 125 个测试、93% 行覆盖率、CI 全绿；真实 LLM 样例端到端跑通，评测报告 JSON/Markdown 落盘可复现。

## 版本三（算法评测侧重）

1. 设计并实现带评测体系的 LLM 需求工程 Agent：Pydantic 约束抽取 + 四角色 LLM 审查 + RAG 引用注入 + 沙箱目标循环。
2. 构建 12 条人工评审视角样例集（golden 字段组 + 预期问题标签，与实现规则解耦），定义字段完整性、问题召回、去重率指标。
3. 实测（DeepSeek-chat）：管线成功率 12/12、问题召回 93.8%；同时量化模型过度标注（粗粒度标签精确率约 22.7%），作为收敛护栏的设计动机。
4. 把评审提示词拆成命名变体，用同一套样例做对比并给出可复现的选优规则（先过滤问题数超预算的变体，再取召回最高、列表最短者）；实测三变体中 baseline 召回 90.0% 胜出，coverage_first 精确率更高但成功率掉到 75%。
5. 为 Agent 循环与选优流程设计可离线复现的行为测试：用确定性 provider 替身覆盖工具调用、验收失败回灌、步数上限、工具越界、并列打破等路径。
6. 输出可复现评测报告（reports/eval 与 reports/tuning 的 JSON+MD）与逐条问题明细，指标口径可审计。

## 使用提醒

- 指标口径必须写清：12 条样例、golden 为人工评审视角、DeepSeek-chat 实测；扩样例集或换模型后重新运行 `uv run reqpilot eval` 再改简历数字。
- 精确率约 22.7% 是粗粒度 (角色,类别) 标签命中率，主动讲成"模型过度标注 → 需要护栏"的工程动机，别回避。
- 简历统一写"独立设计与实现"。不写团队、不写业务方、不写线上用户，被问到就直说是个人项目。
- Agent 循环的价值点在于"完成判定不采信模型"和"工具执行有边界"，讲的时候优先讲这两句。

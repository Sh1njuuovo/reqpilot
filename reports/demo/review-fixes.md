# 需求评审阻塞问题处理结论

本文件针对 `issues.json` 中 severity 为 `critical` 或 `major` 的全部问题（ISSUE-001 ~ ISSUE-020，共 20 条）逐条给出处理结论，并确认 `tasks.md` 已覆盖对应整改任务。

处理结论类型：
- **已整改**：需求/设计已补充明确规则，可直接进入开发。
- **转整改任务**：结论为需在研发阶段落实，已映射到 tasks.md 中的整改任务。

---

## 一、critical 问题（ISSUE-001 ~ ISSUE-005）

### ISSUE-001 幂等键未定义，无法保证重复提交不产生重复单据
- **结论**：已整改。明确幂等键由客户端在提交前生成 `requestId`（UUID），随请求提交；服务端以 `requestId + 申请人ID` 建立唯一索引，重复请求命中唯一键时返回首次落库结果。申请单编号由服务端在幂等键首次落库时生成，规则为 `AP + yyyyMMdd + 6位序列`。
- **覆盖任务**：T-026（幂等键字段与唯一索引设计）、T-027（幂等提交接口实现）。

### ISSUE-002 提交按钮缺少防重复点击与幂等反馈
- **结论**：已整改。提交按钮点击后立即置为禁用并展示加载态；前端生成幂等键随请求提交；重复提交返回已有单据并提示“申请已提交，请勿重复操作”。
- **覆盖任务**：T-028（提交按钮防重复点击与幂等反馈）。

### ISSUE-003 审批状态枚举未定义取值与流转规则
- **结论**：已整改。审批状态枚举取值定义为：`待提交 / 审批中 / 已通过 / 已驳回 / 已撤回`；流转路径为 待提交→审批中→（已通过 | 已驳回），审批中→已撤回，已驳回→待提交（重新提交）。
- **覆盖任务**：T-029（审批状态枚举与流转规则定义）。

### ISSUE-004 缺少审批人角色与审批操作定义
- **结论**：已整改。补充“审批人”角色（可由审批管理员兼任），定义各级审批操作：通过、驳回、加签、转办，并明确各操作对应的状态流转与权限。
- **覆盖任务**：T-030（审批人角色与审批操作定义）。

### ISSUE-005 自动重试与幂等提交的冲突未定义
- **结论**：已整改。幂等键由客户端首次提交时生成并在重试中复用；服务端以 `幂等键 + 申请人` 做唯一约束；重试次数上限 3 次，退避间隔 1s/2s/4s；超限后返回明确失败状态并允许手动重试（仍复用同一幂等键）。补充验收用例“首次成功但响应超时后重试仍只产生一条单据”。
- **覆盖任务**：T-031（自动重试策略与幂等复用实现）。

## ISSUE-002（critical / frontend / interaction）

- 处理：提交点击后立即置为禁用并展示加载态；前端在首次提交时生成幂等键随请求提交；重复提交返回已有单据并提示“申请已提交，请勿重复操作”。
- 覆盖任务：T-028（frontend，依赖 T-027）。

## ISSUE-003（critical / product / logic）
- 结论：**接受，需整改**。审批状态枚举未定义取值与流转规则。
- 处理：明确枚举值（待提交/审批中/已通过/已驳回/已撤回）及允许的状态流转图。
- 覆盖任务：T-029（product）。

## ISSUE-004（critical / product / completeness）
- 结论：**接受，需整改**。缺少审批人角色与审批操作定义。
- 处理：补充审批人角色（或明确审批管理员兼任），定义各级审批操作（通过、驳回、加签、转办）及流转规则。
- 覆盖任务：T-030（product，依赖 T-029）。

## ISSUE-005（critical / test / logic）
- 结论：**接受，需整改**。自动重试与幂等提交的冲突未定义。
- 处理：幂等键由客户端首次提交生成并随重试复用，服务端以幂等键+申请人做唯一约束；定义重试上限（3 次）、退避间隔与超限提示；补充“首次成功但响应超时后重试仍只产生一条单据”的验收用例。
- 覆盖任务：T-031（backend，依赖 T-027）。

## ISSUE-006（major / backend / logic）
- 结论：**接受，需整改**。重试语义未定义，与幂等存在冲突风险。
- 处理：重试必须复用同一幂等键；明确重试次数上限与退避间隔；区分可重试错误（网络超时、5xx）与不可重试错误（参数校验失败、4xx）；重试耗尽后返回明确失败状态并允许手动重试（仍用同一幂等键）。
- 覆盖任务：T-031（backend）。

## ISSUE-007（major / backend / permission）
- 结论：**接受，需整改**。“查看自己提交的记录”缺少数据隔离与越权校验定义。
- 处理：服务端所有查询/详情/导出接口强制注入当前登录用户维度过滤（基于用户 ID 而非姓名字符串）；管理员走独立全量入口；按编号直接访问做归属校验，越权返回 403；补充接口级权限矩阵。
- 覆盖任务：T-032（backend，依赖 T-001）。

## ISSUE-008（major / backend / consistency）
- 结论：**接受，需整改**。分页规则自相矛盾且未定义排序与导出策略。
- 处理：统一分页口径（页码/页大小或游标），明确默认排序字段与方向，导出不受分页限制并说明导出范围。
- 覆盖任务：T-033（backend，依赖 T-001）。

## ISSUE-009（major / product / logic）
- 结论：**接受，需整改**。审批状态枚举与多级审批流转模型缺失。
- 处理：与 ISSUE-003 合并，统一给出状态枚举与多级流转模型。
- 覆盖任务：T-029、T-030（product）。

## ISSUE-010（major / frontend / interaction）
- 结论：**接受，需整改**。分页与分批加载规则不明确。
- 处理：明确分页参数、每页条数与“超过 100 条分批加载”的触发与边界语义，前端按统一规则实现。
- 覆盖任务：T-033（backend）、T-024（frontend）。

## ISSUE-011（major / frontend / completeness）
- 结论：**接受，需整改**。缺少列表空态、加载态与错误态设计。
- 处理：补充列表空态、加载态、错误态（含重试入口）的交互与文案。
- 覆盖任务：T-034（frontend，依赖 T-024）。

## ISSUE-012（major / frontend / interaction）
- 结论：**接受，需整改**。缺少提交失败自动重试的交互与状态定义。
- 处理：定义重试中的加载态、重试次数提示、重试耗尽后的失败态与手动重试入口。
- 覆盖任务：T-028（frontend）、T-031（backend）。

## ISSUE-011（major / frontend / 缺少列表空态、加载态与错误态设计）
- 结论：采纳。列表页需定义空态、加载态、错误态三种状态。
- 处理：空态展示引导文案与“新建申请”入口；加载态使用骨架屏/加载指示；错误态展示错误信息与“重试”按钮。由 T-034 落地。

## ISSUE-012（major / frontend / 缺少提交失败自动重试的交互与状态定义）
- 结论：采纳。前端需定义重试中的交互与状态反馈。
- 处理：提交失败自动重试期间展示“提交中/重试中”状态并禁用按钮；重试耗尽后展示失败提示与手动重试入口，手动重试复用同一幂等键。由 T-028、T-031 落地。

## ISSUE-013（major / product / 表单字段校验规则缺失）
- 结论：采纳。需补齐各字段的必填、类型、长度、格式等校验规则。
- 处理：明确申请人、金额、业务类型等字段的校验规则与错误提示文案。由 T-035 落地。

## ISSUE-014（major / product / 分页规则在功能需求与约束中重复且未定义排序）
- 结论：采纳。合并重复的分页描述并统一排序规则。
- 处理：以单一权威定义描述分页参数与默认排序（如按提交日期倒序），消除功能需求与约束中的重复表述。由 T-033 落地。

## ISSUE-015（major / product / 历史记录导出需求缺少细节）
- 结论：采纳。需补充导出的范围、字段、格式与触发方式。
- 处理：明确导出字段集合、文件格式（如 CSV/XLSX）、导出条数上限与异步/同步方式。由 T-036 落地。

## ISSUE-016（major / test / 自动重试策略缺失，与幂等存在冲突风险）
- 结论：采纳。需定义可测试的重试策略。
- 处理：明确重试次数上限、退避间隔、可重试错误类型，并补充“首次成功但响应超时后重试仍只产生一条单据”的用例。由 T-031 落地。

## ISSUE-017（major / backend / 分页与“超过100条分批加载”的语义与边界未定义）
- 结论：采纳。需统一分页与分批加载语义。
- 处理：明确分页大小、超过 100 条时的分批加载触发条件与边界（含恰好 100 条、101 条等场景）。由 T-033 落地。

## ISSUE-018（major / product / 审批状态枚举值未穷举，状态流转规则缺失）
- 结论：采纳。需穷举状态枚举并给出流转规则。
- 处理：与 ISSUE-003、ISSUE-009 合并处理，输出完整枚举与状态流转图。由 T-029 落地。

## ISSUE-019（major / backend / 导出功能缺少范围、格式与权限边界定义）
- 结论：采纳。需定义导出的数据范围与权限边界。
- 处理：普通用户仅可导出本人记录，管理员可导出全量；导出接口复用数据隔离逻辑，越权返回 403。由 T-036 落地。

## ISSUE-020（major / backend / 金额字段缺少取值范围与精度校验规则）
- 结论：采纳。需定义金额的取值范围、精度与边界校验。
- 处理：明确金额上限、小数位数（如 2 位）、正数约束及超限错误提示。由 T-035 落地。
